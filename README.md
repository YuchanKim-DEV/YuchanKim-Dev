### Project 2. STT 솔루션 납품

`2026.02 ~ 2026.06` &nbsp; 실시간 음성 수신 TCP 서버 · STT 결과 전달 컨슈머

**① 특정 STT 엔진 서버로 부하 쏠림**
- **문제** &nbsp;배포 후 모니터링 중 엔진 서버 하나만 CPU 200%를 사용하는 것을 발견. 음성 인식 지연과 누락으로 이어짐
- **원인** &nbsp;gRPC는 연결 하나를 오래 재사용하는데, 로드밸런서는 연결 단위로만 분산해 한번 연결된 서버로 통화가 계속 몰림
- **시행착오** &nbsp;연결을 여러 개로 늘려 나눠 보냈지만, 연결이 유지되는 한 쏠림이 다시 생김
- **해결** &nbsp;연결을 주기적으로 새로 맺되, 기존 연결은 진행 중인 통화가 끝날 때까지 기다렸다 닫도록 해 통화를 끊지 않고 재분산
- **결과** &nbsp;최고 CPU **200% → 80% 이하**

**② 결과 전달 지연 (처리 대기 1만 건 이상)**
- **문제** &nbsp;고객사로 결과를 전달하는 컨슈머에 처리 대기(LAG)가 1만 건 이상 쌓임
- **원인** &nbsp;응답을 기다리는 동기 호출이라 처리량이 부족했고, 상대가 이미 끊은 연결을 재사용해 오류 발생. 새벽처럼 메시지가 없을 때는 네트워크 장비가 유휴 연결을 끊어 소비가 멈춤
- **시행착오** &nbsp;재시도 횟수를 늘렸지만 동기 구조에서는 지연이 해소되지 않음
- **해결** &nbsp;비동기 호출 + 동시 요청 수 제한으로 전환, 연결 재사용 시간 조정, 브로커 연결 유지 설정
- **결과** &nbsp;처리 대기 **1만 건 이상 → 대부분 0건** (평균 3~10건)

**③ 상담사 전환 시 대화가 뒤섞이는 문제**
- **문제** &nbsp;통화가 다른 상담사로 넘어가면 대화 순서가 뒤섞이고, 이전 상담사 대화에 섞여 들어가며, 중복 번호로 전달이 거절됨
- **원인** &nbsp;전환 시 통화 ID는 그대로인데 연결이 끊겼다 다시 맺어지면서 문장 번호가 기대와 다르게 넘어옴
- **해결** &nbsp;통화·상담사·채널 단위로 문장 번호를 직접 다시 매기고, 같은 통화는 한 작업자가 순서대로 처리하도록 분배

### Project 3. STT 솔루션 납품

`2025.12 ~ 2026.02` &nbsp; 실시간 STT 결과 수집 · 개인정보 마스킹

**① 24시간 서비스 중 배포·종료 시 데이터 유실 위험**
- **문제** &nbsp;24시간 통화가 들어오는 서비스라, 버전 교체나 종료 때 처리 중이던 데이터가 사라질 위험
- **시행착오** &nbsp;종료 요청을 보내도 메시지 수신이 한 번에 멈추지 않는 경우를 실제로 겪음
- **해결** &nbsp;신규 유입 차단 → 멈출 때까지 단계적으로 재시도하고, 끝내 안 멈추면 내부 진입 자체를 차단 → 대기열과 처리 중 작업이 0이 될 때까지 기다린 뒤 종료. DB 저장이 끝난 메시지만 완료로 기록해, 중간에 죽어도 재기동 후 다시 처리
- **결과** &nbsp;고객사가 오픈 이후 매일 무작위 1,000건을 검수하는 환경에서 **누락 문의 0건**

**② 개인정보 마스킹 정확도 80%**
- **문제** &nbsp;문장 단위로 마스킹하니 개인정보를 놓치는 경우가 많음
- **원인** &nbsp;문맥으로 판단하는 NLU 엔진에 문장을 하나씩만 전달해, 여러 문장에 걸친 개인정보를 판단하지 못함
- **해결** &nbsp;통화가 끝나는 시점에 통화 전체를 합쳐 한 번에 마스킹한 뒤 문장별로 다시 나눠 저장
- **결과** &nbsp;마스킹 정확도 **80% → 98%**

**③ PoC 단계 문장 유실**
- **문제** &nbsp;PoC 중 통화 후반부 문장이 유실됨
- **원인** &nbsp;한 통화의 메시지가 여러 파티션으로 나뉘어 들어와, 파티션별 작업자 구조에서는 통화 종료가 먼저 처리되고 늦게 온 문장이 버려짐
- **해결** &nbsp;분배 기준을 파티션에서 통화 ID로 바꿔, 같은 통화는 항상 같은 작업자가 순서대로 처리

### Project 4. STT 솔루션 납품

`2025.08 ~ 2025.12` &nbsp; STT → 유형 분류 → 요약 파이프라인

**① 하루 2만여 건 결과 누락 장애**
- **문제** &nbsp;오픈 이후 다른 파트에서 전달해야 할 분류·요약 결과가 주기적으로 누락, 한 번은 하루치 약 2만 건이 누락
- **시행착오** &nbsp;처음엔 누락분을 수동으로 메웠고, 대형 장애 이후 기간 단위로 누락분을 채우는 복구 앱을 만들어 복구
- **해결** &nbsp;사후 복구에 그치지 않고, 결과가 비거나 실패로 오면 저장된 STT 텍스트로 분석 엔진을 직접 다시 호출하는 실시간 재시도 추가
- **결과** &nbsp;이후 **누락 0건**

**② 같은 통화 중복 처리**
- **문제** &nbsp;같은 통화가 두 번 처리돼 데이터가 중복 저장되고, 웹 조회에서 오류 발생
- **원인** &nbsp;요청 경로가 두 곳이라 자동 전송 후 상담사가 수동으로 한 번 더 요청하는 경우가 있었고, 서버 2대 구성이라 메모리 기반 중복 차단이 서버 간에 공유되지 않음
- **시행착오** &nbsp;기존 테이블에 유니크 인덱스를 거는 안을 검토했으나, 운영 중인 대용량 테이블이라 락 위험이 있어 배제
- **해결** &nbsp;두 서버가 함께 보는 중복 차단 전용 테이블을 두고, `INSERT IGNORE` 한 번으로 원자적으로 판정

**③ 상담사·고객 대화가 구분되지 않는 버그**
- **문제** &nbsp;운영 중 상담 이력을 확인하다가 모든 대화가 상담사 대화로 저장되는 버그를 직접 발견
- **원인** &nbsp;엔진이 보내는 화자 표기 형식이 코드 기준과 달라 매칭 실패. 발화 수 비교 방식은 동수일 때 한쪽으로 쏠리는 결함이 있음
- **해결** &nbsp;화자 표기 정규화, 발화 수 비교 제거, 기본 매핑에 상담사 확정 멘트 보정을 더해 판별
- **결과** &nbsp;화자 구분 정확도 **85% → 90%** (엔진 개선이 필요한 영역이라 목표 96%는 미달)
