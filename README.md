### Project 2 · STT 솔루션 납품

`2026.02 ~ 2026.06` &nbsp; 실시간 음성 수신 TCP 서버 · STT 결과 전달 컨슈머 · 최대 480채널 · AWS

| 해결한 문제 | Before | After |
|:---|:---:|:---:|
| STT 엔진 부하 쏠림 | CPU **200%** | CPU **80% 이하** |
| 결과 전달 지연 | 처리 대기 **1만 건+** | 평시 **0건** |

- **부하 쏠림** → gRPC 장기 연결이 로드밸런서 뒤 한 서버에 고정되는 원인을 찾아, 통화를 끊지 않는 연결 회전으로 재분산
- **전달 지연** → 동기 호출을 비동기로 전환하고, 끊긴 연결 재사용·유휴 연결 종료 문제를 함께 해결

<br/>

### Project 3 · STT 솔루션 납품

`2025.12 ~ 2026.02` &nbsp; 24시간 실시간 상담 STT 결과 수집 · 8개 인스턴스 운영

| 해결한 문제 | Before | After |
|:---|:---:|:---:|
| 배포·종료 중 데이터 유실 위험 | 종료 시 처리 중 데이터 유실 가능 | 누락 문의 **0건** |
| 개인정보 마스킹 정확도 | **80%** | **98%** |

- **무중단 배포** → 수신 차단 → 대기열 소진 → 종료로 이어지는 단계적 종료 절차 설계. 고객사가 매일 무작위 1,000건을 검수하는 환경에서 누락 0건 유지
- **마스킹 정확도** → 문장 단위로 보내던 마스킹 엔진 연동을 통화 단위로 바꿔, 엔진이 앞뒤 문맥을 보고 판단하도록 개선

<br/>

### Project 4 · STT 솔루션 납품

`2025.08 ~ 2025.12` &nbsp; 상담 STT → 유형 분류 → 요약 파이프라인 · 서버 2대 운영

| 해결한 문제 | Before | After |
|:---|:---:|:---:|
| 분석 결과 누락 | 하루 **2만여 건** 누락 장애 | 누락 **0건** |
| 서버 간 중복 처리 | 중복 저장 · 조회 오류 | 서버 간 **원자적 차단** |

- **결과 누락** → 복구 앱으로 누락분을 채우고, 결과가 비면 분석 엔진을 직접 재호출하는 실시간 재시도로 재발 차단
- **중복 처리** → 락 위험이 있는 운영 테이블 인덱스 추가 대신, 전용 테이블 + `INSERT IGNORE`로 판정
